Write Frolvy feedback simply: per issue three short lines - **Bug** (one sentence), **How to see it** (2-3 steps), **Request** (one sentence). No workaround stories, no long explanations, no code dumps beyond the one call that shows it. Same for the email to hello@frolvy.com (English, reply in the existing thread) and for the log `work/frolvy_feedback.md` (one table row per issue).

**Why:** user 2026-11-04 after the second feedback mail: "ghi feedback đơn giản hơn" - the logs and mails had grown long (date, scene, repro code, workaround, consequences, quoted request).

**How to apply:** whenever a Frolvy bug turns up, add one row to the table in `work/frolvy_feedback.md`; when the user says to send, mail only those rows not yet sent, three lines each. Ask before sending unless the user already said to send.
